REST (Representational State Transfer) is a set of constraints for designing networked APIs. Instead
of inventing custom verbs, you use HTTP methods (GET, POST, PUT, PATCH, DELETE) and descriptive URLs to
communicate intent.

<Figure src="/posts/images/rest-api-flow.svg" alt="Arrows showing a client sending GET and receiving 200 OK" caption="Clients send HTTP verbs, servers answer with resources plus status codes." />

### Design Checklist

- Identify resources first (e.g., `/posts`, `/posts/:id/comments`).
- Rely on HTTP status codes to communicate success and errors.
- Return consistent JSON shapes and include hyperlinks (HATEOAS) when useful.
- Document versioning and authentication early.

### Example Request

```
GET /posts/42
Accept: application/json
```

A clean JSON response with the post body, author, and links to related resources makes it easy for
clients to navigate your API without surprises.
